PART 01

Passive vs Active Information Gathering

#

1. What is reconnaissance?

Reconnaissance is the information-gathering phase of a penetration test. It builds an understanding of the target before vulnerability validation or exploitation. The tester seeks domain names, IP addresses, employees' email addresses, technologies, software versions, operating systems, open ports, services, subdomains and exposed infrastructure.

2. Passive information gathering

🔍
PASSIVE RECONNAISSANCE DEFINITION
Passive reconnaissance: Collect information without directly interacting with the target's systems. It generally has a lower chance of detection, but information may be incomplete or outdated.

  • WHOIS lookups, Google Dorking and Google Hacking Database (GHDB) searches.

  • Shodan searches, public document analysis, email harvesting and social-media research.

  • Reviewing public job advertisements and other publicly available organisational information.

  • Website mirroring of publicly served pages for offline inspection.

WHOIS

WHOIS is a domain registration database. A lookup may disclose the registrar, registrant information (unless privacy protection is used), registration and expiry dates, and name servers. It helps build an organisational and DNS-infrastructure profile.

bash — Kali Linux Terminal
$ whois example.com
WHOIS field Why it matters
Registrant / organisation May identify the domain owner.
Registrar Identifies the domain registration provider.
Creation / expiry dates Shows domain registration history.
Name servers Provides clues about DNS infrastructure.
Registrant email May provide a contact or organisational clue; often
privacy-protected.

Website mirroring

Website mirroring creates a local copy of publicly accessible website content for offline review. Tools mentioned in the lecture include HTTrack (Website Copier) and Website Ripper Copier. A local copy may help inspect HTML, JavaScript, comments, references, directories and publicly served files.

Reverse IP lookup

Reverse IP lookup identifies other websites hosted on the same server as a given IP address or domain. A service such as YouGetSignal may reveal co-hosted sites and expand the list of infrastructure requiring review. Shared hosting does not automatically mean that one site's weakness compromises another.

Google Hacking and GHDB

Google Hacking uses advanced search operators to find information indexed by search engines. The Google Hacking Database (GHDB), associated with Offensive Security, collects search queries known as Google Dorks.

Example query Purpose
site:example.com filetype:pdf Find indexed PDF documents on a domain.
Example query Purpose
intitle:"index of" "parent directory" Find indexed directory-listing pages.
inurl:admin login.php Find pages with administrative URL patterns.

Google Dorks may expose documents, usernames, email lists, backup files, directory listings or administrative pages. The lecture also mentions Xcode Exploit Scanner as an automated tool that uses common Google Dorks to search for issues such as SQL injection (SQLi) and Cross-Site Scripting (XSS). Search results are leads, not proof of a vulnerability.

FOCA and document metadata

FOCA analyses publicly available documents and extracts metadata. The lecture lists DOC, PDF and XLS files and search sources such as Google, Yahoo and Bing. Metadata is information about a file rather than its visible content; examples include author names, internal file paths, software versions and document properties.

3. Active information gathering

⚡
ACTIVE RECONNAISSANCE DEFINITION
Active reconnaissance: Directly interacts with target systems by sending network packets or requests. It can provide current information but is more likely to generate logs or alerts in IDS, IPS, firewall and SIEM systems.

  • Nmap host discovery, port scanning, service/version detection and OS detection.

  • SMB, LDAP and SNMP enumeration.

  • Direct webserver fingerprinting and other authorised network probes.

Dimension 🔍 Passive ⚡ Active
Target engagement No direct interaction with target systems Direct interaction
Detection risk Generally lower Generally higher
Freshness May be outdated Usually current at scan time
Examples WHOIS, GHDB, Shodan, FOCA, Nmap, enum4linux, snmpwalk
TheHarvester

Passive does not mean automatically legal or harmless. Publicly finding information does not authorise its use. Legality and permission depend on the activity, applicable law and engagement authorisation.

4. Reconnaissance decision flow

  • Confirm written authorisation, scope and Rules of Engagement.

  • Start with passive sources: WHOIS, Google Dorks, GHDB, FOCA, TheHarvester, Shodan and public sources.

  • Assess whether the intelligence is sufficient; identify gaps.

  • If authorised and necessary, proceed to active discovery and enumeration.

  • Produce an attack-surface profile containing prioritised targets, exposed services, candidate credential risks and configuration concerns.

PART 02

Webserver Fingerprinting & DNS Enumeration

#

5. Webserver fingerprinting

Webserver fingerprinting identifies the webserver and technologies used by a website by examining responses to HTTP requests. Useful clues include the Server header, X-Powered-By header and Set-Cookie header. Responses may disclose server software, versions, frameworks, modules, libraries or application clues.

Header Potential information
Server Webserver software and sometimes its version.
X-Powered-By Framework or technology information.
Set-Cookie Cookie names, attributes and application clues.

Tools: Burp Suite, WhatWeb and Netcraft

  • Burp Suite: An intercepting proxy that allows a tester to inspect HTTP requests and responses. The lecture also mentions Paros and WebScarab.

  • WhatWeb: Active web fingerprinting tool with more than 900 plugins. It may identify server banners, framework versions, JavaScript libraries, analytics identifiers, email addresses and SQL errors.

  • Netcraft: Uses information from its online database / Internet Survey. It is treated in the lecture as passive, unlike WhatWeb, which sends requests directly to the target.

whatweb slashdot.org reddit.com

6. DNS fundamentals

The Domain Name System (DNS) translates between domain names and IP addresses. Forward lookup resolves a hostname to an IP address; reverse lookup resolves an IP address to a hostname.

Lookup Direction Record / example
Forward DNS Hostname IPv4 address A record: dig example.com A
Reverse DNS IP address hostname PTR record under in-addr.arpa

For reverse IPv4 DNS, reverse the IP octets and append .in-addr.arpa. For example, 208.80.152.201 becomes 201.152.80.208.in-addr.arpa.

bash — Kali Linux Terminal
$ dig example.com A nslookup example.com nslookup -type=mx example.com dig 201.152.80.208.in-addr.arpa PTR

DNS resolution

  • The client sends a query to its resolver/cache.

  • If the answer is not cached, the resolver may query a Root Name Server.

  • The Root server refers the resolver to the appropriate Top-Level Domain (TLD) server.

  • The TLD server refers it to the authoritative name server.

  • The authoritative server returns the requested DNS record.

The lecture presents dig as a powerful DNS query utility that supports different record types and displays details such as TTL. nslookup is a simpler DNS query utility.

7. DNS Zone Transfers (AXFR)

A DNS Zone Transfer is a legitimate DNS replication mechanism. If a server is misconfigured to allow unauthorised external zone transfers, a requester may obtain many or all DNS records for a zone. Exposed records may reveal hostnames, subdomains, mail servers and other infrastructure.

DNSenum is a Perl-based tool described as automating zone-transfer attempts, subdomain brute-forcing and Google scraping. Fierce performs forward and reverse lookup, subdomain brute-forcing and zone-transfer attempts.

bash — Kali Linux Terminal
$ ./dnsenum.pl zonetransfer.me fierce -dns example.com -wordlist hosts.txt

The lecture recommends checking for a misconfigured zone transfer before attempting subdomain brute-forcing. Only test domains included in the authorised scope.

8. DNS cache snooping

DNS Cache Snooping attempts to determine whether a DNS record is already cached on a DNS server. A cached record may provide clues about domains queried by users of that resolver.

  • Nonrecursive method: Set the Recursion Desired (RD) flag to 0 and query the DNS server. An immediate answer may indicate that the record is cached.

  • Recursive method: Send a normal recursive query and compare the returned TTL with the expected initial or authoritative TTL. A lower TTL may suggest a cached record.

The lecture describes the nonrecursive method as more direct and the recursive method as less accurate because TTL comparisons are indirect and can be affected by upstream caches.

PART 03

Subdomains, Load Balancers, CloudFlare & Shodan

#

9. Subdomain discovery

A subdomain is an additional hostname under a domain. For example, mail.example.com, vpn.example.com, dev.example.com, admin.example.com and ftp.example.com are possible subdomains of example.com.

Subdomain discovery matters because older, development or administrative systems may be less protected than the main website. Tools and approaches in the lecture include Google Dorking, Fierce and WolframAlpha. Fierce can test possible hostnames from a wordlist.

fierce -dns example.com -wordlist hosts.txt

A discovered subdomain is a lead for assessment, not proof that the service is vulnerable. Confirm ownership, scope and exposure before further testing.

10. Load balancer detection

A load balancer distributes incoming traffic across multiple servers to improve performance, availability, scalability and reliability.

Type Layer / behaviour Possible indicator
Layer 4 Transport-layer distribution, often based on A hostname may resolve to multiple IP
network/transport information. addresses.
Layer 7 Application-layer proxy can route HTTP Different requests may reach different
requests to different backends. backend servers while the visible IP
remains the same.

The lecture mentions lbd, a Bash script for detecting Layer 4 and Layer 7 load balancers.

bash — Kali Linux Terminal
$ host www.google.com lbd www.google.com

11. CloudFlare and origin-server exposure

CloudFlare can operate as a reverse proxy between visitors and a website's origin server. Visitors connect to CloudFlare, which forwards requests to the origin and returns responses. This can conceal the origin IP address.

The lecture discusses three conceptual ways an origin IP might be exposed. These are for understanding and authorised assessment only:

  • Historical DNS records: Old DNS records may contain an origin IP from before the proxy was enabled.

  • Subdomain misconfiguration: Some subdomains may point directly to the origin rather than using the proxy.

  • Mail server / MX and headers: MX records identify mail servers. The lecture discusses examining email headers, especially Received headers, for infrastructure clues.

Method Underlying condition
Historical DNS Origin IP was publicly exposed in earlier DNS data.
Subdomain A subdomain is configured to point directly to the origin.
Mail headers Mail infrastructure or message headers disclose relevant server
details.

12. Shodan

Shodan is a search engine for internet-connected devices and services. Unlike conventional search engines that primarily index web pages, Shodan collects information about exposed devices such as printers, cameras, routers, industrial control systems and network infrastructure.

Device banners may reveal device type, software/firmware information and service details. The lecture gives these example searches:

bash — Kali Linux Terminal
$ admin+1234 cisco-ios "last-modified" default-password

The lecture associates these queries with searching for common credential text, Cisco IOS banners and the default-password keyword. A Shodan result is an observation, not permission to connect to or test the device.

13. Email harvesting

Email harvesting collects publicly available email addresses associated with an organisation. TheHarvester is a Python-based OSINT tool that can collect information from supported search engines and sources such as PGP key servers and LinkedIn.

theHarvester -d example.com -b all

  • -d specifies the target domain.

  • -b specifies the data source; all requests all supported sources.

The lecture also mentions Pipl as a people-search service for cross-referencing publicly collected information. Email harvesting may help build employee lists, infer organisational relationships and identify social-engineering risks. It does not establish that an account is vulnerable.

PART 04

Active Scanning with Nmap

#

14. Introduction to Nmap

Nmap (Network Mapper), developed by Fyodor / Gordon Lyon, is a network discovery and security auditing tool. It is used to discover live hosts, identify open ports, detect services and versions, attempt OS detection, investigate firewall behaviour and save scan results. The lecture lists Kali Linux, Parrot Security OS, BlackArch and Pentoo as distributions that include Nmap.

15. Host discovery

Option Example Purpose
-PR nmap -PR 192.168.1.50 ARP discovery, useful on local Ethernet
networks.
-sn nmap -sn 192.168.1.0/24 Host discovery only; no port scan.
-PS nmap -PS22,80,443 192.168.1.50 TCP SYN discovery probes to specified
ports.

The lecture describes -sn discovery as using a combination of probes such as ICMP Echo, TCP SYN to 443, TCP ACK to 80 and ICMP timestamp (probe behaviour can vary with privileges and scan context).

16. TCP and UDP scanning

Scan Command How it works / characteristics
SYN scan (-sS) sudo nmap -sS target Half-open TCP scan. Sends SYN; an open
port typically replies SYN-ACK; Nmap
sends RST rather than completing the
handshake. Normally requires elevated
privileges.
TCP Connect (-sT) nmap -sT target Uses the operating system's connect call
and completes the TCP three-way
handshake. Does not normally require root;
may be more visible in logs.
UDP (-sU) sudo nmap -sU --top-ports 50 Scans UDP services. No TCP handshake
target applies. Open UDP services may not reply;
closed ports may return ICMP Port
Unreachable.

TCP three-way handshake: client sends SYN; server responds SYN-ACK; client sends ACK. A SYN scan stops short of completing the handshake and normally sends RST after receiving SYN-ACK.

UDP open|filtered: This result is ambiguous. Nmap cannot tell whether the UDP port is open but silent or whether a firewall is filtering probes. It is not proof that the port is open.

17. Port targeting

bash — Kali Linux Terminal
$ nmap -p 80 <target> nmap -p 80,443 <target> nmap -p 1024-3000 <target> nmap -p U:53,111,137,T:21-25,80,139,443 <target> nmap -p- <target>

The -p option specifies ports. Use commas for individual ports and hyphens for ranges. Prefixes U: and T: distinguish UDP and TCP. The -p- option scans all TCP ports (1–65535) in the usual TCP scan context.

-iL Read targets from a file.
--exclude Exclude a host.

-O versus -A: -O focuses on OS detection. -A enables a broader set of features, including OS detection, version detection, script scanning and traceroute.

20. Timing templates

Flag Name Description
-T0 Paranoid Extremely slow.
-T1 Sneaky Very slow.
-T2 Polite Slower / less aggressive.
-T3 Normal Default timing.
-T4 Aggressive Faster; lecture recommendation for a

Faster is not always better. Aggressive timing may result in packet loss or false negatives, where an open service is not correctly identified.

21. Stealth and evasion-related flags

Flag Function
-Pn Skip host discovery and treat target as online.
-sA ACK scan; can help assess firewall filtering behaviour.
-sF / -sN / -sX FIN, NULL and XMAS TCP scans using unusual TCP flag patterns.
-sI Idle / zombie scan using a third host as an indirect scanning source.
-b FTP bounce scan.
-f Fragment packets.
-D Use decoy addresses.
-e Choose a network interface.

These options do not guarantee invisibility. Network monitoring may still detect unusual traffic, and their use must be explicitly permitted by the Rules of Engagement.

22. Worked Nmap command

sudo nmap -sS -sV -O -p- -T4 -oA scan_results 192.168.1.50
Part Meaning
sudo Run with elevated privileges.
-sS TCP SYN half-open scan.
-sV Service/version detection.
-O OS detection.
-p- Scan all TCP ports.
-T4 Aggressive timing template.
-oA scan_results Save output in all major formats.
192.168.1.50 Target IP address.

This command combines a full TCP port scan with service/version detection and OS detection, then saves the results. It is suitable only when the target and scan intensity are within the authorised scope.

23. Common Nmap mistakes

  • Running a SYN scan without sufficient privileges may cause Nmap to use a different scan method, such as TCP Connect.

  • Treating UDP open|filtered as definitely open is incorrect; the result is ambiguous.

  • Using -T5 automatically does not improve accuracy. Timing should suit the network and engagement.

Service Enumeration: SMB, LDAP & SNMP

#

24. What is service enumeration?

Service enumeration follows initial host and port discovery. It collects more detailed information from services, such as users, groups, shared resources, directory attributes, network interfaces and device configuration.

25. SMB enumeration

SMB (Server Message Block) is a network protocol used for file and printer sharing and other resource access, commonly in Windows environments. The lecture lists TCP 445 and TCP 139.

What enumeration may reveal:

  • Share names and access permissions / ACLs.

  • Whether anonymous SMB access (a null session) is allowed, including access attempts involving IPC\$.

  • User accounts, groups and other information available through RPC.

A null session is an anonymous SMB connection. If permitted, it may expose information without normal authentication. SMB findings can inform later investigations involving credential risks, NTLM-related hash capture, lateral movement and access to shared resources.

Tool Purpose / example
enum4linux Windows/SMB enumeration. enum4linux -a 192.168.1.50
smbclient Command-line interaction with SMB shares.
rpcclient Interact with RPC services and retrieve Windows account / domain
information.

26. LDAP enumeration

LDAP (Lightweight Directory Access Protocol) accesses and manages directory information. It is common in enterprise environments and Active Directory-integrated systems. The lecture lists TCP/UDP 389 for LDAP and TCP 636 for LDAPS.

LDAP enumeration may identify naming contexts and directory partitions, whether anonymous bind is permitted, user attributes, group membership and Organisational Unit (OU) hierarchy.

Attribute Meaning
displayName User's display name.
mail Email address.
memberOf Groups the user belongs to.
ldapsearch -x -H ldap://192.168.1.50 -b "dc=example,dc=com"

In this command, -x selects simple authentication, -H specifies the LDAP server URI, and -b sets the base distinguished name (DN) from which the directory search begins. Anonymous queries only return information if the directory permits them.

27. SNMP enumeration

SNMP (Simple Network Management Protocol) is used to monitor and manage network devices such as routers, switches, servers and printers. The lecture identifies UDP 161 as the default query port.

Versions: SNMP v1, v2 and v3. In SNMP v1 and v2c, community strings act as shared access values. Common examples are public and private. Older v1/v2c community strings are not encrypted in transit; SNMP v3 provides stronger security capabilities.

SNMP data may disclose system information, network interfaces, routing tables, running processes, device configuration and MIB information. MIB means Management Information Base.

Tool Purpose / example
Onesixtyone Tests community strings from a wordlist. onesixtyone -c
communities.txt 192.168.1.50
Snmpenum Enumerates information after a valid community string is available.
snmpenum.pl 192.168.1.50 public linux.txt
SolarWinds Toolset Network administration tools that can query and display SNMP /
MIB information.

28. SMB vs LDAP vs SNMP

Dimension 📁 SMB (139/445) 👥 LDAP (389/636) 📡 SNMP (161/162)
Ports TCP 445, 139 TCP/UDP 389; TCP 636 UDP 161
LDAPS
Main data Shares, users, groups Users, groups, OUs, attributes System data, MIB, interfaces,
processes
Anonymous / weak access Null session / IPC$ Anonymous bind Weak or default community
strings
Tools enum4linux, smbclient, rpcclient ldapsearch, ldeep, onesixtyone, snmpenum,

Easy way to remember: SMB = shared resources and Windows information. LDAP = directory structure and identity information. SNMP = network-device monitoring and management information.

Integrated Reconnaissance Scenario

#

29. Scenario

The lecture asks students to design a reconnaissance plan for a mock organisation with a public website, an SNMP-enabled router and employees active on job websites. The goal is to combine passive and active techniques and produce a one-page attack-surface summary.

Phase 1: Passive reconnaissance

  • WHOIS: Identify registration information, registrar and name servers.

  • Google Dorking: Search for indexed documents and exposed directory listings.

  • TheHarvester: Collect publicly available email addresses and related OSINT.

  • Shodan: Review internet-facing device and service information.

Phase 2: Active reconnaissance

bash — Kali Linux Terminal
$ nmap -sn 192.168.1.0/24 sudo nmap -sS -sV -O -p- -T4 -oA router_scan 192.168.1.1 sudo nmap -sU -p 161 --top-ports 50 -T4 192.168.1.1

First discover live hosts. Then scan the in-scope router for TCP services, versions and OS clues. Separately investigate UDP 161 for SNMP availability.

Phase 3: Service investigation and conclusions

If SNMP is exposed, assess community-string security using an approved wordlist and, if permitted, enumerate relevant system information. Employee email and job-site information may help identify organisational relationships and social-engineering exposure. Windows systems discovered during scanning may be prioritised for in-scope SMB or LDAP enumeration.

Suggested one-page attack-surface report

  • Scope and authorisation reference.

  • Discovered domains, subdomains, hosts and exposed services.

  • Service versions and relevant device information.

  • Credential-related and anonymous-access risks.

  • Potential configuration weaknesses and supporting evidence.

  • Risk-based priorities and recommended next steps.

32. Commonly confused concepts

Concepts Difference
WhatWeb vs Netcraft WhatWeb actively sends HTTP requests; Netcraft uses an existing
information database.
-sS vs -sT SYN is half-open; Connect completes the TCP handshake.
-O vs -sV -O attempts OS detection; -sV detects service versions.
-T4 vs -T5 T4 is a faster practical balance; T5 is extremely aggressive and
may reduce reliability.
Forward vs reverse DNS Hostname to IP versus IP to hostname.
SMB vs LDAP Shared resources / Windows information versus directory / identity
information.
Onesixtyone vs Snmpenum Tests community strings versus enumerates SNMP data using a
known valid string.
