Web Enumeration & the OWASP Top 10

#

Web enumeration is the reconnaissance phase applied to a web application. It transforms an unknown target into a structured attack surface. Exploitation without enumeration is guessing: enumeration tells you where to inject, what technology to target, and which OWASP category is even possible.

What gets mapped

  • Pages and endpoints: visible and linked

  • Parameters: GET/POST, cookies, headers

  • Hidden directories: found via forced browsing

  • Technologies: server, framework, CMS, JS libraries

  • Input points: forms, search bars, URL params, upload fields

The OWASP Top 10 is a community-driven, risk-prioritized list of the most critical web app security risks. It is not exhaustive, not a legal compliance requirement, and not a scanning tool.

MODULE 02

Injection: SQLi & Command Injection

#

Injection flaws occur because user-controlled input is interpreted as actual commands or parameters by the application.

SQL Injection (conceptual; Week 4 deep-dive)

Occurs when user-controlled input is passed into SQL queries, letting an attacker manipulate the query outcome.

SQL Query / Payload
> Payload: ' OR '1'='1 Template: SELECT * FROM users WHERE username = '$input' AND password = '$pass'; Result: SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '...';

Because '1'='1' always evaluates to TRUE, authentication is bypassed.

Command Injection (Week 6 deep-dive)

Occurs when server-side code (e.g. PHP) makes a system call on the hosting machine, and an attacker abuses that call to run operating system commands on the server. A simple whoami or file read alone is not catastrophic, but it can escalate to a reverse shell. Some netcat variants lack the -e flag, so bash, python or perl one-liners may be needed.

Escalation chain

  • Recon: find an input point that hits system() / passthru()

  • Confirm: inject ;whoami or &&id

  • Persist: write a webshell or schedule a callback

  • Escalate: push a reverse shell back to the attacker

  • Pivot: internal enumeration and lateral movement

Blind vs. Active

  • Active: output is visible in the response, e.g. PHP passthru(\$command_string) returns output to the browser.

  • Blind: output is NOT returned in the HTML. Confirm via time-based or out-of-band (OOB) techniques.

Post-confirmation enumeration

OS Commands
🐧 Linux whoami / id, uname -a, ip addr (ifconfig), ps aux, netstat -ano
🪟 Windows whoami, ver / systeminfo, ipconfig /all, tasklist, netstat -ano

Defenses

  • Allow-listing (preferred): compare input to known-safe values and reject everything else; this closes unknown edge cases.

  • Stripping dangerous characters: fragile; bypassable via encoding, nesting or novel metacharacters.

  • Use dedicated sanitization libraries rather than hand-rolling.

MODULE 03

Broken Authentication & Sensitive Data Exposure

#

Broken Authentication (Week 7 deep-dive)

HTTP(S) is stateless, so each request is independent. Session cookies track authenticated users across requests; flaws in authentication or session management break the trust model.

  • Brute-force attacks: repeated guessing of credentials

  • Weak credentials: e.g. "password1", guessable without brute-forcing

  • Weak session cookies: predictable values that let an attacker forge a session

Logic-flaw example (leading space): if user admin exists, re-registering as " admin" (note the leading space) creates a new user that has the same rights as the real admin. This is a developer input-sanitization mistake, distinct from brute-forcing.

Mitigations: strong password policy, automatic lockout after N failed attempts, and Multi-Factor Authentication (MFA).

Sensitive Data Exposure (modern name: Cryptographic Failures, Week 9)

A web app "accidentally divulges sensitive data": customer PII, financial data, or technical data such as credentials.

  • Flat-file database exploitation: SQLite databases stored under a website's public root can be downloaded directly and queried offline.
SQL Query / Payload
> SELECT custID, custName, creditCard, password_hash FROM users; PRAGMA table_info(customers); -- reveals column names/types

  • Hash cracking: submit the MD5 hash to CrackStation, an online tool backed by a massive wordlist. Example: 5f4dcc3b5aa765d61d8327deb882cf99 cracks to password.

  • Cracked credentials can then be reused for credential-stuffing attacks elsewhere.

MODULE 04

XML External Entity (XXE)

#

XML (eXtensible Markup Language) defines rules for encoding documents in a format that is both human- and machine-readable. Full exploitation depth returns in Week 8 alongside SSRF/SSTI/CORS.

XML & DTD basics

  • The XML prolog is required at the top (declares version and encoding).

  • Every document needs a single ROOT element.

  • XML is case-sensitive: must close with .

  • A DTD (Document Type Definition) declares structure. #PCDATA = parseable character data (text between tags).

  • XXE occurs when a parser resolves external entities (e.g. a SYSTEM URI).

Payloads

XML External Entity (XXE) Payload
> <!-- DTD Entity Declaration & Usage --> <!DOCTYPE userInfo [ <!ENTITY name "feast"> ]> <userInfo><lastName>&name;</lastName></userInfo> <!-- Parsed output: &name; is replaced with "feast" --> <!-- Malicious SYSTEM Entity (Local File Disclosure) --> <?xml version="1.0" encoding="UTF-8"?> <!DOCTYPE root [ <!ENTITY read SYSTEM "file:///etc/passwd"> ]> <root>&read;</root> <!-- Vulnerable parser substitutes &read; with /etc/passwd contents -->

SYSTEM signifies that the entity references an external resource via a URI.

Substitution flow

Attacker sends XML with a malicious DOCTYPE > parser resolves the entity > server reads the file from the filesystem > contents are substituted into the entity > response is returned (in-band) or data is sent to an attacker server (OOB).

Impact categories

  • Local file read (LFD / arbitrary file disclosure)

  • Denial of Service (e.g. Billion Laughs attack)

  • Server-Side Request Forgery (SSRF via internal HTTP endpoints)

  • Port scanning of internal infrastructure

  • Remote Code Execution (e.g. via PHP expect:// wrapper)

Two exploitation modes

  • In-band (classic): parsed file contents or entity reflections are returned directly in the immediate HTTP response.

  • Out-of-band (blind): no reflection or direct errors; the attacker forces the server to exfiltrate data to an external listener (DNS/HTTP). The immediate HTTP response does not contain the data.

Broken Access Control, Security Misconfiguration & XSS

#

Broken Access Control (Week 7 deep-dive)

Restricted pages or functions (e.g. admin-only) are reachable by unauthorized users.

  • Parameter tampering: the attacker modifies a value such as acct=9999 directly and accesses another user's account if ownership isn't verified.

  • Forced browsing: compare /user/dashboard with /admin/user-management. Reachability by an unauthenticated or non-admin user is the flaw.

  • IDOR (Insecure Direct Object Reference): changing /api/v1/accounts/1234/statements to 1235 may expose another customer's data. The parameter itself isn't the flaw; the absent ownership validation is.

Security Misconfiguration (Week 9 deep-dive)

  • Poorly configured cloud storage permissions

  • Unnecessary enabled features, services or accounts

  • Default accounts with unchanged passwords

  • Overly detailed error messages

  • Missing security headers or revealing Server: headers

🚨
CASE STUDY · DYN / MIRAI BOTNET (OCTOBER 2016)
Textbook Security Misconfiguration at Ecosystem Scale: The Mirai botnet used a list of 63 default username/password pairs to compromise exposed Telnet services on IoT devices and routers, then launched a DDoS flood that took Dyn (a DNS provider) offline. Amazon, Twitter, Netflix, GitHub, Xbox Live and PlayStation Network were disrupted for hours across three attack waves, a textbook misconfiguration failure at ecosystem scale.

Cross-Site Scripting (Week 5 deep-dive, with CSRF)

Type Description
🔥 Stored (Persistent) Most dangerous. Payload is persisted in the database (e.g. comment field); every visitor
triggers it.
⚡ Reflected Payload is part of the victim's own request; requires tricking them into clicking a crafted link.
🌐 DOM-based Manipulates the Document Object Model client-side; no server round-trip needed.

Example payload types: a popup (alert("Hello World")), HTML override via document.write, a keylogger script, and a mini port-scanning script. XSS is NOT just popups: it enables session hijacking, keylogging and internal port scanning.

Insecure Deserialization, Components & OWASP ZAP

#

Insecure Deserialization (#8)

Low exploitability (case-by-case, no universal tool) but potentially severe (DoS to RCE). Serialization converts complex data into a transmittable format (like drawing a map for a tourist who doesn't share your language); deserialization is the reverse. The flaw occurs when untrusted, attacker-supplied serialized data is deserialized and executed without validation.

Components with Known Vulnerabilities (#9)

Outdated libraries with public CVEs; attackers chain known CVEs against unpatched dependencies. Examples: old Apache Struts (Equifax 2017), EOL log4j 1.x bindings, outdated jQuery/Bootstrap.

Insufficient Logging & Monitoring (#10)

Absence of logging for authentication attempts, access-control failures and input-validation failures lets attackers persist undetected. Tie-back: Mirai's initial compromise went undetected on many devices for this reason.

Why OWASP ZAP?

ZAP is completely open source and free: no premium version, no paywalled features, no proprietary code.

Synthesis & Closing Scenario Model Answer

#

Common misconceptions

  • "OWASP Top 10 is one week's content." In reality it is partly a roadmap: 9 of the 10 categories get dedicated deep-dive weeks (Weeks 4-10).

  • "XSS is just popups." It enables session hijacking, keylogging and internal port scanning; Stored XSS persists in the DB and hits every visitor.

  • "Passive scanning carries zero legal/ethical risk." Even passive scanning generates traffic; always have written authorization (scope, rules of engagement) before scanning any non-owned target.

Common lab pitfalls

  • Skipping the ZAP certificate import step.

  • Confusing the Traditional Spider with the Ajax Spider.

  • Forgetting to set DVWA Security Level to Low before the authenticated-scan walkthrough.

  • Treating Fuzzer results under 8 characters as valid credentials.

  • Treating the OWASP Top 10 as exhaustive.
