Course Glossary & Key Terms

Terminology and definitions for all weeks of the penetration testing course.

Week 1

Terminology

  • Ethical hacking — Authorized practice of attacking systems to discover weaknesses before adversaries do.
  • Penetration testing — Formal, contracted, RoE-bounded subset of ethical hacking.
  • White-hat / Black-hat / Grey-hat — Classifications by authorization + intent + disclosure behavior.
  • PTES — Penetration Testing Execution Standard; 7-phase pentest lifecycle.
  • RoE — Rules of Engagement; signed document governing the engagement.
  • CFAA — 18 U.S.C. § 1030; U.S. federal anti-hacking statute.
  • GDPR — EU Regulation 2016/679; governs processing of EU personal data.
  • OSINT — Open-Source Intelligence; passive recon from public sources.
  • CVSS — Common Vulnerability Scoring System; severity 0.0–10.0.
  • Safe-harbor — Legal protection for researchers acting within a bug-bounty program's scope and disclosure rules.

Week 5

Summary & Key Terminology

  1. XSS = attacker-run JavaScript in a web app. Three types: DOM (browser-side, iframe), Persistent (stored server-side, e.g., True-Client-IP), Reflected (single request, e.g., id param).
  2. Same payload primitive (<iframe src="javascript:alert(`xss`)">) works across all three XSS types — only the injection vector changes.
  3. Persistent XSS injection points are NOT limited to form fields — HTTP headers (True-Client-IP, X-Forwarded-For) are equally valid.
  4. CSRF = forged request from victim's browser, exploiting the app's trust in the session cookie. No script runs on the target site.
  5. Core CSRF defenses: anti-CSRF tokens, SameSite cookies, re-auth for sensitive actions, Origin/Referer (supplementary only).
  6. Juice Shop also demonstrates Injection (W4), Broken Auth (W7/10), Sensitive Data Exposure (W9), Broken Access Control (W7) — NOT this week's scope.
  • XSS — Cross-Site Scripting; attacker-run JavaScript in a web app's context.
  • DOM (Special) — XSS that executes via the HTML environment; uses <script> or iframe tags; runs entirely client-side.
  • Reflected XSS — JavaScript that runs on the client-side; payload travels in the request URL/form and is reflected back unsanitised.
  • XFS — Cross-Frame Scripting; alias for the iframe+javascript: URI technique used for DOM XSS.
  • Persistent XSS — JavaScript that runs when the server loads a page containing it; payload is stored (e.g., in a database); fires for every visitor.
  • True-Client-IP — HTTP header similar to X-Forwarded-For; tells the server/proxy the client's IP; vulnerable injection vector for Persistent XSS.
  • CSRF — Cross-Site Request Forgery; forged request from victim's browser exploiting session-cookie trust.
  • Anti-CSRF token — Unique unpredictable token embedded per form/request and validated server-side.
  • SameSite — Cookie attribute (Strict/Lax) preventing the browser from sending the cookie on cross-site requests.
  • HttpOnly — Cookie attribute preventing JavaScript from reading the cookie value (XSS defense, NOT a CSRF defense).
Week 6

Terminology

  • LFI — Local File Inclusion — include-family call with user-controlled local path
  • RFI — Remote File Inclusion — include-family call with a remote URL (needs allow_url_include=On)
  • allow_url_include — PHP setting that permits include-family functions to fetch remote URLs; default Off
  • php://filter — Wrapper that reads file source as base64 — leaks PHP source code
  • Path Traversal — Manipulating file path input to escape the intended directory
  • Null byte — %00 — older PHP truncates strings at it (file.php%00.jpg)
  • Command Injection — User input reaches a shell command unfiltered
  • Blind vs Active — No output reflected vs output reflected (Week 3 callback)
  • $IFS — Shell Internal Field Separator — default whitespace; bypasses space filters
  • File Upload — Endpoint that writes user files to disk; RCE if name+content are attacker-controlled
  • Magic bytes — First bytes identifying a file format (e.g. GIF89a;); spoofable
  • getimagesize() — PHP function that trusts magic bytes — bypassed by prepending a valid image header
  • Defense-in-depth — Stacking orthogonal controls so no single bypass compromises the system
