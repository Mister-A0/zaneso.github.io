MODULE 01

Introduction to Ethical Hacking

#

1.1 What is Ethical Hacking?

Ethical hacking is the practice of testing computer systems, networks, and applications to identify security weaknesses before malicious attackers exploit them. Its purpose is to improve security, not to damage systems or steal information.

Three conditions form the foundation of authorized testing:

  1. Written authorization: Permission must be obtained from the system owner.

  2. Defined scope: The systems, IP addresses, applications, and permitted activities must be specified.

  3. Defensive purpose: Testing is performed to identify weaknesses and help improve security.

🔑
KEY PRINCIPLE
Technical ability or good intentions do not create permission to access a system.

1.2 Types of Hackers

Type Description
White Hat An authorized security professional who identifies vulnerabilities to improve security.
Black Hat A malicious attacker who exploits vulnerabilities for personal gain or harmful purposes.
Grey Hat Someone who may access or test systems without authorization, even if the intention is not
necessarily malicious.

The central distinction is authorization, not simply the hacker's intention.

1.3 Ethical Hacking vs. Penetration Testing

Ethical hacking is a broad concept that includes authorized security activities. Penetration testing is a structured assessment in which testers attempt to exploit vulnerabilities within an agreed scope. A penetration test follows a defined methodology and produces documented findings and recommendations.

1.4 Red Team, Blue Team, and Purple Team

Team Role
⚔️ Red Team Offensive security. Simulates attackers and attempts to compromise systems to discover
weaknesses.
🛡️ Blue Team Defensive security. Protects systems, monitors activity, detects attacks, and responds to incidents.
🔮 Purple Team Collaboration between Red and Blue Teams to improve detection and defense.

1.5 Legal and Ethical Responsibility

The lecture refers to United States v. Auernheimer (2012) to illustrate that good intentions do not make unauthorized access lawful. Always obtain permission before testing, scanning, or accessing systems.

MODULE 02

Why Do We Need Penetration Testing Methodologies?

#

A penetration testing methodology provides a structured process for conducting security assessments. Without a methodology, testing can become inconsistent, incomplete, or difficult to reproduce.

2.1 Importance of Methodologies

  • Consistency: Different testers follow a similar process.

  • Quality: Important testing activities are less likely to be missed.

  • Repeatability: Another tester can reproduce the assessment.

  • Defensibility: Results can be explained and supported by evidence.

  • Organization: Testing activities follow a logical sequence.

2.2 Common Methodologies and Frameworks

Framework Main focus
OWASP Testing Guides Web application security testing.
PTES The complete penetration testing lifecycle.
PCI DSS Security requirements for environments handling payment card data.
PTF Penetration testing framework.
NIST SP 800-115 Technical guide for information security testing and assessment.
OSSTMM Structured security testing methodology.

OWASP vs. PTES: OWASP focuses mainly on application security testing, while PTES provides a broader process covering the engagement from preparation through reporting.

A methodology provides the process; individual tools perform specific technical tasks within that process.

MODULE 03

PTES – Penetration Testing Execution Standard

#

PTES organizes penetration testing into seven phases. The phases provide a logical lifecycle, although an engagement may revisit earlier phases as new information is discovered.

Phase Name Main question
Phase 1 Pre-Engagement Interactions Are we authorized, and what can we test?
Phase 2 Intelligence Gathering What information can we collect?
Phase 3 Threat Modeling What assets and threats matter most?
Phase 4 Vulnerability Analysis What weaknesses exist?
Phase 5 Exploitation Can we exploit those weaknesses?
Phase 6 Post-Exploitation What could an attacker do after access?
Phase 7 Reporting What did we discover, and how can it be fixed?

Phase 1: Pre-Engagement Interactions

This is the preparation phase. Before technical testing begins, the penetration tester and client agree on the conditions of the engagement.

  • Define the scope of the penetration test.

  • Obtain written authorization.

  • Agree on the Rules of Engagement (RoE).

  • Identify permitted systems and IP addresses.

  • Establish communication channels and escalation contacts.

  • Define testing dates, times, and prohibited activities.

  • Determine the testing approach.

Testing type Information available
Black Box Little or no internal information.
Grey Box Partial information or limited access.
White Box Extensive internal information, such as architecture or source code.

Common documents: Authorization Letter (formal permission), RoE (how testing must be conducted), NDA (confidentiality), MSA (general business relationship), and DPA (data protection responsibilities).

💡
EXAM TIP & CORE CONCEPT
Do not start scanning before authorization and scope have been established.

Phase 2: Intelligence Gathering

Intelligence gathering collects information about the target to understand its attack surface and identify possible entry points.

Passive vs. Active Reconnaissance

Type Description Examples
Passive Collects information without directly
interacting with the target's systems.		 Public websites, search engines, public DNS records,
Certificate Transparency logs, public documents.
Active Directly interacts with the target system. Port scanning, service detection, directory enumeration,
network discovery.

Important tools and commands

crt.sh: Investigates publicly logged TLS/SSL certificates and can help discover subdomains.

bash — Kali Linux Terminal
$ curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq

Nmap: Used for network discovery, port scanning, and service identification.

bash — Kali Linux Terminal
$ nmap -sS -sV 192.168.1.10

ffuf: Used for web directory and file enumeration.

bash — Kali Linux Terminal
$ ffuf -u http://target.com/FUZZ -w wordlist.txt
HTTP code Meaning
200 OK OK – resource successfully accessed.
301 Redirect Moved Permanently.
302 Redirect Found – temporary redirect.
403 Client Error Forbidden – access denied.
404 Client Error Not Found.
500 Server Error Internal Server Error.
💡
EXAM TIP & CORE CONCEPT
Passive reconnaissance avoids direct interaction with the target; active reconnaissance involves direct interaction.

Phase 3: Threat Modeling

Threat modeling identifies what needs protection, who might attack it, and how attacks could happen. It helps prioritize the most important threats.

  • Identify important assets.

  • Identify the attack surface.

  • Identify potential threat actors.

  • Analyze possible attack paths.

  • Prioritize threats according to risk.

Crown Jewels: The organization's most valuable assets, such as customer databases, financial information, and intellectual property.

Attack Surface: All possible points through which an attacker might interact with or compromise a system.

Threat Actors: Individuals or groups that may attempt an attack, such as cybercriminals, insiders, hacktivists, or nation-state attackers.

A vulnerability affecting a highly valuable asset (Crown Jewels) and being relatively easy to exploit receives the highest remediation priority.

Target 2013 breach: The lecture uses this incident to illustrate how attackers can exploit a third-party supplier as an entry point into a larger organization. Organizations should therefore consider third-party relationships and indirect attack paths.

Phase 4: Vulnerability Analysis

This phase identifies weaknesses in the target environment. The tester analyzes information gathered during reconnaissance and determines which vulnerabilities may exist.

  • Automated vulnerability scanning.

  • Manual vulnerability verification.

  • Identifying insecure configurations.

  • Reviewing exposed services.

  • Analyzing credentials and authentication weaknesses.

Term Meaning
False Positive A tool reports a vulnerability that does not actually exist.
False Negative A real vulnerability is not detected.

Vulnerability Analysis vs. Exploitation: Vulnerability analysis identifies and verifies weaknesses; exploitation attempts to use a weakness to gain access or demonstrate its impact.

Finding a vulnerability does not necessarily mean it has been successfully exploited.

Phase 5: Exploitation

Exploitation attempts to use identified vulnerabilities to gain access to a target system or demonstrate their security impact.

  • Validate vulnerabilities.

  • Demonstrate whether a weakness is exploitable.

  • Obtain initial access when authorized.

  • Evaluate the possible consequences of exploitation.

SearchSploit: A command-line tool used to search the Exploit Database.

bash — Kali Linux Terminal
$ searchsploit apache

To update its database:

bash — Kali Linux Terminal
$ searchsploit -u

A vulnerability may exist without being practically exploitable under the current conditions. Exploitation provides evidence of impact, but must remain within the agreed authorization and safety limits.

Phase 6: Post-Exploitation

After obtaining access, the tester evaluates what an attacker could potentially achieve. The purpose is to measure the impact of a successful compromise.

  • Privilege escalation.

  • Access assessment.

  • Lateral movement.

  • Pivoting.

  • Persistence testing when explicitly authorized.

  • Identifying accessible sensitive resources.

  • Demonstrating business impact.

Concept Meaning Example
Vertical privilege
escalation		 Moving from a lower-privileged account to a
higher-privileged account.		 A normal user gains administrator
privileges.
Horizontal privilege
escalation		 Accessing another user's resources while
maintaining a similar privilege level.		 User A accesses User B's account
information.
Pivoting Using a compromised system as a stepping stone to
reach other systems.		 A compromised host is used to access
another network segment.

Post-exploitation must be controlled. Testers should avoid unnecessary access to real customer data and clean up testing artifacts when the engagement requires it.

Phase 7: Reporting

Reporting communicates the assessment results to the organization. A penetration test is not complete simply because vulnerabilities were discovered; findings must be clearly documented. Documentation should begin during the engagement.

Main report components

  1. Executive Summary: For management and non-technical stakeholders. Explains the overall security condition, major risks, business impact, and important recommendations.

  2. Technical Findings: For technical teams. Each finding should include a description, affected system, evidence, reproduction steps or proof of concept, risk and impact, and recommended remediation.

  3. Risk and Severity: CVSS can be used to communicate vulnerability severity.

  4. Remediation Recommendations: Explains how vulnerabilities can be fixed or mitigated.

CVSS score Severity
0.0 None
0.1–3.9 Low
4.0–6.9 Medium
7.0–8.9 High
9.0–10.0 Critical

Record evidence, timestamps, commands, and observations throughout the engagement rather than waiting until the end.

MODULE 04

Rules of Engagement (RoE) and Legal Frameworks

#

Rules of Engagement define the boundaries and conditions under which a penetration test is conducted. They help protect both the organization and the penetration tester.

4.1 Main Components of RoE

Component Purpose
Scope Defines what can be tested.
Time Windows Defines when testing is allowed.
Prohibited Actions Identifies activities that are not allowed.
Escalation Path Defines whom to contact if an issue occurs.
Data Handling Explains how collected information must be protected.
Authorization Provides formal approval for testing.

For example, an organization may authorize testing of two specific IP addresses while prohibiting denial-of-service attacks, social engineering, testing third-party systems, or accessing real customer data. The tester must respect those limits.

4.2 Authorization Letter vs. RoE

Authorization Letter: Confirms that the tester has permission to conduct the assessment. Rules of Engagement: Explain exactly how the assessment may be conducted. An authorization letter does not automatically grant unlimited permission.

4.3 Legal Frameworks

CFAA – Computer Fraud and Abuse Act: A United States federal law addressing certain unauthorized access and computer-related offenses. The lecture uses it to emphasize the legal risks of accessing systems without proper authorization.

GDPR – General Data Protection Regulation: An EU data protection regulation. The lecture highlights these provisions:

GDPR article Main topic
Article 5 Principles relating to personal data processing.
Article 25 Data protection by design and by default.
Article 33 Notification of personal data breaches.

Relevant principles include data minimization, protection of personal information, limiting unnecessary access, and appropriate data handling.

4.4 Cases and Bug Bounty Programs

The lecture also refers to United States v. Swartz (2011) , an alleged bank penetration tester over-scanning incident in 2017, and the Uber CISO Joe Sullivan case. These examples emphasize authorization, scope, responsible disclosure, and proper incident handling.

A bug bounty program allows security researchers to report vulnerabilities under defined rules. Examples of platforms include HackerOne and Bugcrowd.

Bug Bounty Formal Penetration Testing
Often open to multiple researchers. Usually conducted by an assigned testing team.
Focuses on reporting eligible vulnerabilities. Follows an agreed testing plan.
Scope and reward rules are program-defined. Scope and RoE are agreed with the client.
May operate continuously. Usually occurs during a defined engagement.

A bug bounty program does not authorize testing outside its stated scope. Safe harbor protections depend on the program's terms and applicable law.

Questions and answers

💡 Active Recall & Self-Quiz Mode Test yourself before expanding answers
Q1

Can the tester start scanning the host?

EXAM ANSWER:

No. Written authorization, scope, and RoE must be established first.

Q2

Which PTES phase includes scanning?

EXAM ANSWER:

Scanning is part of Phase 2: Intelligence Gathering, specifically active reconnaissance. However, its place in PTES does not make it authorized in this scenario.

Q3

What is missing before testing begins?

EXAM ANSWER:

Written authorization, defined scope, RoE, testing schedule, communication and escalation procedures, and data-handling requirements.

Q4

What legal concerns exist?

EXAM ANSWER:

Because the environment contains EU personal data, GDPR requirements must be considered, including data minimization and appropriate protection of personal information.

⭐
TAKEAWAY LESSON
Technical ability does not replace legal authorization.

Kali Linux Practical Lab Preparation

#

The lecture introduces basic commands used to prepare a Kali Linux environment for penetration testing.

6.1 Check network connectivity

bash — Kali Linux Terminal
$ ping -c 3 8.8.8.8

Sends three ICMP packets to test connectivity.

6.2 Check network interfaces

bash — Kali Linux Terminal
$ ip -br a

Displays network interfaces and their IP addresses in a brief format.

6.3 DNS lookup

bash — Kali Linux Terminal
$ dig +short example.com

Returns DNS information, such as resolved IP addresses.

6.4 Check Nmap version

bash — Kali Linux Terminal
$ nmap --version

Displays the installed Nmap version.

6.5 Update SearchSploit

bash — Kali Linux Terminal
$ searchsploit -u

Updates the local Exploit Database search index.

6.6 Nmap practical command

bash — Kali Linux Terminal
$ sudo nmap -sS -sV -O --top-ports 1000 -T3 --reason -oA nilelab_recon 10.10.0.0/24
Option Meaning
sudo Runs the command with elevated privileges.
-sS Performs a TCP SYN scan.
-sV Detects service versions.
-O Attempts operating system detection.
--top-ports 1000 Scans the 1,000 most common ports.
-T3 Uses Nmap's normal timing template.
--reason Shows why Nmap assigned a particular port state.
-oA Saves output in three formats.
nilelab_recon Output filename prefix.
10.10.0.0/24 Target network range.
⚠️
LAB SAFETY & AUTHORIZATION WARNING
The -oA option generates three files: .nmap (normal output), .xml (XML output), and .gnmap (grepable output). Only run scanning commands against systems and networks that you own or have explicit permission to test.

6.7 Common Lab Problems

Problem Possible cause or response
No network connectivity Check the VM network mode.
No IP address Check DHCP configuration.
Wrong target network Verify the assigned IP range.
Scanning takes too long Review scan options and timing.
Missing evidence Save scan output and document findings.
Scope violation Stop testing and verify authorization.

The lecture also mentions the following DHCP command, assuming the interface name is correct:

bash — Kali Linux Terminal
$ sudo dhclient eth0

Final Revision: The Complete Penetration Testing Process

#

  1. Pre-Engagement Interactions: Obtain permission, define scope, and establish RoE.

  2. Intelligence Gathering: Collect information and discover the attack surface.

  3. Threat Modeling: Identify valuable assets, threats, and attack paths.

  4. Vulnerability Analysis: Discover and verify security weaknesses.

  5. Exploitation: Attempt to exploit weaknesses within the authorized scope.

  6. Post-Exploitation: Evaluate the impact of successful access.

  7. Reporting: Document the results and recommend remediation.
